# Test vectors for MOR's core

Published test vectors for every layer of MOR's core: the pieces every act is made of, signatures, and verdict vectors (complete acts with the verdict each must get, and the rule that decides it). An implementation of the eight texts in `spec/` should reproduce every value here.

**Stand-ins until the freeze.** The six MIR hashes the acts name (`IDENTITY`, `ENVELOPES`, `TEXT`, `MONEY`, `AGREEMENTS`, `DEVELOPMENT`) are fixed only at the freeze, from the frozen texts (Development rule 26). Until then every vector uses stand-ins, SHA-256 of a label, listed in each file that uses them (`verdicts.json`, `"mirs"`). At the freeze the files are generated again with the real hashes; every act id changes, no verdict does.

**Test data.** Every key, seed and secret here is derived from a label and is test data, labelled so. None may be used for anything else.

All byte strings are lowercase hexadecimal.

**Size.** `verdicts.json` is about 4.22 MB (4,217,372 bytes), most of it SLH-DSA-SHA2-128f chain signatures (17,088 bytes each), each held once in the pool and named by every case that needs it.

## The verdict vectors

Each case in `verdicts.json` names the acts a verifier holds (complete bytes, in the pool), the facts that are not acts (inclusion proofs a home served; anchors the verifier checked; the rail's answers for a receipt or claim, that it is valid and which payment its proof is, which the core never reads itself; a private act's content key, as its recipient holds it; where a private act was found), a question and its verdict. The questions are explained in the file's `about`. Every act is public save two private link claims, whose keys are stated as facts.

## What changed since the previous edition

- `canonical-text.json`: rules are numbered as Text numbers them, 7 to 12 (they were 1 to 6), and where a string breaks several, the rule given is the first in the order numbered, each rule checked over the whole string (Text rule 13); two cases test that order.
- `cbor.json`: a NaN whose payload needs single width, accepted as a single and refused as a double.
- `open-act.json` and `verdicts.json`: a new content key and nonce for every act (Envelopes rule 9); every act id changed, no earlier verdict did, save as listed here.
