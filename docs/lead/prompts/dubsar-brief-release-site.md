## 2. What the site does for the release

The site is how a reader gets from a message to the signed record and back to us. What has been decided (roadmap steps 10a and 17, F277, F287, F288, and the doors report `docs/dubsar-org-doors-2026-10-09.md`):

- **It is a gateway, not a hub.** MOR's documents are signed acts on relays, never copies on the site (website cMIP, rule 13). The site holds links, and each page is verified in the visitor's browser, showing who signed it.
- **The main door** opens on the first act ("Thank you for the shower…", with the photograph of the Earth). Above the doors is a direct button to "MOR in one page". Then come four doors by what the visitor wants: Read, Build, Run, Use. The scribe is a footnote, which carries the way to reach him. English for now.
- **Fourteen department doors**, as folders of the same site (`dubsar.org/law/` and so on), are unlisted but never hidden. Every message sends two addresses: the main door and the department's own. The first wave mostly gets Build and cryptography. Each door's opening lines and order are Nobody, allegedly's to write.
- **The way back** is always open: the box on the site; the public reporting identity (F287), where reports are signed acts, kept and answered in the open; the contact address; and GitHub issues as a mirror, for those not on MOR yet.
- **The listing of cMIPs and Modules** (F288) is "one listing among any; anyone can run another". Its first purpose is tracking extensions: what people build that the core did not foresee is MOR 2's raw material. It ranks nothing by authority and leaves nothing out on purpose.
- **The repository** is shown through a read-only release browser, with every file checked in the visitor's browser, plus a verified archive per release (F277). GitHub is mirrored until the browser is good enough.
- **Nothing is collected about visitors:** no analytics and no tracking.
