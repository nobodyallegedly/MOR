**The words used for each rule.**
- **STAYS**: no standing entry changes what the rule says. Where an entry names the rule and keeps or confirms it, the row says so; otherwise the row reads "stays as it is" and its other cells are empty.
- **GOES**: the rule leaves and is written nowhere else.
- **MOVES**: the rule leaves Agreements for another text: Envelopes, the MICS (the shared language of all the layers), the layer below, or a companion document.
- **CHANGES**: the rule stays in Agreements and a standing entry changes what it says. What changes is said in plain words; no new wording is written.
- **Two readings** (written "STAYS or MOVES", "STAYS or CHANGES" and so on): the standing entries can be read two ways for this rule. Both are given, with the number of the reading in the list further down.

**A cMIP** is a module that an agreement chooses, by naming it in one of its fields (a socket). **Terms** are the act that states what is agreed. **The gate that goes** is short, in the table, for one thing: draft 25 lets an update replace the old Terms only when the old Terms' update condition answers valid *and* the new version has the signatures its own `in_force` rule asks; "The two gates" keeps the first check alone.
