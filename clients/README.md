# Clients

The TypeScript clients (build brief: "Rust for the core library, relays and homes; TypeScript for clients"). Each uses the core library through WebAssembly (`wasm/`, crate `mor-wasm`), so every act is made and judged by the same Rust code as the relays; a client only fetches, stores and shows.

| Folder | What | Roadmap |
| --- | --- | --- |
| `genesis/` | The genesis client: test identities, routes, encryption keys, rotations, key delivery. | step 5 |
| `repo/` | The repo client: a test collective under a founding agreement, releases of the code as signed manifests, verification of every file. | step 5a |
| `longform/` | The long-form text format: reading, rendering to HTML with the plain text one tap away, and the Text MIR's bound checked on every rendering; a document as a text act, published and read back verified. | step 8 |
| `barebone/` | The barebone client: a post with a picture (a text act referring to a JPEG publication, stripped to the picture alone), shown verified; withdrawal. | step 9 |
| `dub/` | Dub (called MOR Post until 13 October 2026; reshaped 16 October 2026, F332): an app on the Mac, no command line, and the same page as a web client at dub.dubsar.org, for testing only (F281). An identity window first (make one, its chain key's words shown once and kept nowhere, hidden before three are asked back; bring one by its signing key's words, which carry its encryption key too; switch between those held; a display name, the naming cMIP; the signing key's words on request); then two tabs: **Public** (the feed of its own posts and the followed, in signed order; post with a picture, optionally to an identity; reply, follow and mute on every post; follow by ID, the people cMIP; a "to you" filter with a count; long-form documents as a link to the reader) and **Private** (the inbox, messages sealed to one identity, a count). No rotation: when its key is changed elsewhere (MOR Safety), it says so and takes the new words. The desk's server and launcher, the site's feed. | step 9b; F332 |
| `reader/` | The web reader, the door: opens by link, verifies in the browser, renders documents and posts, shows the signer's fingerprint; reach the owner by email or by a message sealed over MOR. | step 10 |
| `site/` | Websites on MOR: a site as a signed manifest of its files; a gateway serving it at an address, whose display client checks every page in the visitor's browser and shows who signed it; publish, verify and check from the command line. | step 10a |
| `manage/` | The management page for relays and homes, served by the relay itself at `/manage/`: a browser paired once with a one-time code signs every request; approvals, lists, a limit on new identities, the operator's rotation. | step 11 |
| `collective/` | The collective client: a program on the author's machine with a page in the browser, no command line; releases under one's own name, founding a collective, adding and removing members, signing and verifying releases, leaving; every step read back in plain words from the exact bytes before it is signed. | step 11b |
| `connector/` | The MOR connector for Claude, an MCP server: reads and verifies acts by id or link, says in plain words who signed what and whether it counts (in force as far as the relays asked show); prepares posts, pictures, withdrawals and messages as drafts for MOR Identities, never an Agreements act; it never holds a key nor sends an act. Drafts are files in `~/mor-drafts`, whose format `connector/DRAFTS.md` documents. Installed outside `~/Documents` by `npm run add-to-claude`, since Claude's app may not start a program kept there. | steps 11a, 11c |
| `desk/` | MOR Identities, the owner's desk: a program on the owner's machine with a page in the browser, no command line, holding several test identities; drafts from Claude read in plain words with their digest, approved, declined or sent back with a note; what each identity received (messages, replies, acknowledgements, payments), sorted into to answer, answered and ignored. Machine, allegedly, plugged in: its terms, the owner's own acts answered at once, others' notified until picked, nudges; drafted with Claude through the API under a daily cap. | step 11c; "Claude through the API" |
| `assess/` | The deal-assessment tool: explains an agreement in plain words (who signed, what each party is bound to, the shares and fees, who judges and in what order, how it ends, what is still owed) and flags its obvious risks, each naming the rule or stated cost it rests on. Shared code: the command `mor-assess ID --at URL`, the collective client's readings before signing, and the desk's received terms. Every fact is the core library's. | step 14 |
| `nudge/` | The nudge cMIP (draft 2): an agent's agency terms, the nudge and the pick, made and read; beside an action, the reading anyone can check (within its terms, free or by pick; outside; unknown; unclear; over the count). Used by the desk for Machine, allegedly. | after the rename pass |
| `reports/` | Reports on MOR mirrored on GitHub, both ways (F287): a command run by hand on the author's computer reads the reporting identity's public reports (each from its reporter's own identity) and its answers, checks each, and opens or updates one GitHub issue per report, each answer a comment; for the issues opened on GitHub that the author names after its dry run, prepares the reporting identity's re-publication as a draft for MOR Identities, which signs it on approval, and copies answers back. A private report is never mirrored; nothing is signed by the command; the token never printed. | F287 |

Building any of them needs Node 22 or later, Rust with the `wasm32-unknown-unknown` target, and `wasm-bindgen-cli` of the version the `mor-wasm` crate pins:

```
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129 --locked
```
